# 论文研究专家团（Paper Research Expert Panel, PEP）

一个面向学术研究的多智能体协作包：**1 名统筹者 + 5 名专员**，覆盖从选题到评审的完整链条。

作者：fssk

---

## 一、起因

我最初的想法是让一个通用助手把论文从头做到尾。试过几轮之后放弃了。

同一个会话里，它前面刚说"文献支持这个假设"，后面写讨论时就把这个假设当成已被证实的事实；让它跑统计检验，它会顺手把结论改成措辞更漂亮的版本。

问题不在模型能力，而在角色没有分开。一个同时负责检索、分析、写作和自查的助手，本能地让前后输出保持一致——而不是让它正确。所以我把它拆成几个独立角色，各自只对自己的产出负责，最后单独设一个角色专门挑毛病。

## 二、成员怎么定的

我没有凭直觉分配角色，而是先查了几套已有的科研协作方案，看它们在角色划分上有没有共识：

| 方案 | 角色 / 阶段 |
|------|------------|
| Harvard Kempner 研究所科研管线 | 文献 → 假设 → 设计 → 执行 → 分析 → 写作 |
| ReputAgent 多智能体科研团队 | 约 8 个角色：文献、方法、实验、写作、评审等 |
| 阿里云 AI 科研团队 | 导演 / 文献 / 数据 / 算法 / 写作 |

三套方案的交集很稳定，落在六类职能上：总控、文献、设计、分析、写作、评审。我按这个交集定的人选，没有自己另发明一套。

ReputAgent 的 8 个角色我压到了 5 个——方法和实验并入"设计"与"分析"。理由很实际：在这个规模上继续细分，成员之间协调的开销会超过细分带来的收益。

## 三、结构

统筹者负责接住用户的模糊目标，把它拆成子任务分派下去，再把中间产物汇总成交付物。专员只在自己的职责域内行动，彼此通过结构化的中间产物传递信息，而不是靠上下文猜测。

```
                        研究问题
                           │
                    ┌──────┴──────┐
                    │   毕成稿    │  统筹 / 编排 / 交付
                    └──┬───┬───┬──┘
          ┌────────┬───┴───┴───┬────────┐
          ▼        ▼           ▼        ▼
       林阅川    计方成      舒析     朱执笔
       文献      设计        分析     写作
                                        │
                                        ▼
                                      顾平
                                   0–100 评审
```

我把评审放在交付前，且让它独立于写作与分析——这是整套设计里我最不想妥协的一点，理由见第五节。

## 四、成员与分工

| 成员 | 角色 | 负责 |
|------|------|------|
| **毕成稿** | 研究总监 | 选题澄清、任务分派、进度跟踪、最终交付 |
| **林阅川** | 文献综述研究员 | 系统检索、综述撰写、研究空白分析、引用核验 |
| **计方成** | 研究设计专家 | 假设构建、实验/调研方案、统计方法选型 |
| **舒析** | 数据分析专家 | 统计检验、机器学习实验、学术图表 |
| **朱执笔** | 学术写作专家 | IMRaD 写作、学术润色、期刊格式适配 |
| **顾平** | 同行评审专家 | 0–100 评分、逐条审稿意见、引用与事实核验 |

每名成员都有明确的禁区。设计专家不碰数据运行，写作专家不新增未核验的引用，评审专家只评价不代写。这条约束比角色定义本身更重要——它是防止"越界替对方做决定"的唯一手段。

## 五、评审为什么单独设

让写稿的角色自己检查稿件，本质上是在问作者"你觉得你写得怎么样"。我把生成和评审拆成两个独立角色，评审者看不到写作过程，只看到成品，按原创性、方法严谨性、证据充分性、写作清晰度、规范性五个维度打分，再逐条列 Major / Minor 意见。

它还有一个具体职责：核验引用是否真实存在、数据与结论是否对得上、图表与正文是否一致。这是我最常遇到的失败模式——编造的文献和不存在的图表编号。

评分低于 80 时，稿件退回对应专员重做，不进入交付。

## 六、工作流

- **A 论文全流程**：选题 → 文献 → 假设 → 设计 → 执行 → 分析 → 写作 → 评审，八阶段由统筹者串联。
- **B 文献综述**：由林阅川单独主导，输出综述与研究空白清单，可作为 A 的前置环节。
- **C 论文评审**：任意稿件交给顾平，产出评分与修改清单。
- **单角色直调**：绕过编排，直接指定某名专员做单点任务，比如"只对这个数据集做假设检验并出图"。

## 七、用下来观察到的

- 拆角色之后最明显的变化是**结论不再被美化**。分析角色交出的空结果和负面结果，写作角色不太会再"润色"成正面结论——因为那是另一个角色的产出，它只有一个引用义务。
- 中间产物显式化（检索报告、研究方案、数据集、图表、稿件、审稿意见）让每一步都可回溯。出了错能定位到具体环节，而不是只能整篇重来。
- 代价是慢。多角色串行比单个助手一步到位慢得多，适合真要投出去的稿子，不适合临时凑个提纲。

## 八、还做不到的

1. 成员构成取自公开方案的收敛，没有针对具体学科（实验科学 vs. 计算社会科学）做细粒度调整，方法学偏好目前是通用的。
2. 评审依赖智能体自身的一致性，没有接外部引用库或可复现性检查器，核验是"尽力而为"而非强保证。
3. 没有直连文献数据库，检索能力取决于通用检索的上限。
4. 目前没有任何人类确认节点。涉及高风险结论时，我不建议跳过自己读一遍这一步。

## 九、安装与使用

把本目录整体放入你的专家/插件目录，即可作为「论文研究专家团」调用。整个包是自包含的，删掉目录即卸载。

推荐的上手方式：

1. 「帮我规划一篇 X 方向论文的完整研究路线」
2. 「针对主题 Y 生成系统文献综述与研究空白分析」
3. 把初稿交进去走评审，按修改清单迭代
4. 单点任务：「只对该数据集做假设检验并出图」
