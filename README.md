# 论文研究专家团（Paper Research Expert Panel, PEP）
### 面向学术研究的多智能体协同 SkillHub —— 设计原理、系统架构与应用范式

> 一个由 WorkBuddy 自动构建、面向学术研究的**多智能体专家团（Expert Panel / SkillHub）**。
> 成员构成由对主流科研协作方案的检索与收敛确定，内置论文全流程、文献综述与论文评审三类工作流。

---

## 摘要（Abstract）

随着大语言模型（LLM）在科研辅助中的渗透，单一通用智能体在文献检索、研究设计、统计分析与学术写作等高度专业化环节上已显现能力天花板。本文介绍 **论文研究专家团（Paper Research Expert Panel, PEP）**——一个基于角色专门化（role specialization）与编排式多智能体（orchestrated multi-agent）范式的学术研究 SkillHub。该专家团以"1 名研究总监 + 5 名领域专员"的扁平化结构组织六类核心科研职能，并将主流科研管线抽象为可复用的内置工作流。其成员配置并非主观设定，而是通过对 Harvard Kempner 研究所科研管线、ReputAgent 多智能体科研团队、阿里云 AI 科研团队三类代表性方案的检索与交叉验证后收敛得出，从而在"职责覆盖度"与"协作冗余度"之间取得平衡。本文系统阐述其设计原理、系统架构、成员分工、工作流编排与质量保障机 制，并讨论其局限与未来演进方向。

**关键词**：多智能体系统；科研自动化；角色专门化；文献综述；同行评审；SkillHub

## 1. 引言与背景

现代学术研究的产出链条可抽象为"选题 → 文献 → 假设 → 设计 → 执行 → 分析 → 写作 → 评审"八个相继阶段。任一阶段都需要差异化的知识结构与方法论素养：文献阶段依赖检索策略与批判性综述能力，设计阶段依赖统计功效与实验控制意识，分析阶段依赖推断统计与可视化规范，写作阶段依赖学科话语与出版格式约束。将全部职能压铸于单一提示（prompt）之下，往往导致**角色混淆（role conflation）**与**职责漂移（responsibility drift）**——例如写作智能体越界替代理性问题、分析智能体擅自改写结论。

PEP 的设计回应了这一痛点：以**职责边界清晰、接口契约稳定**的专门化智能体替代"全能型"单体智能体，并由一名研究总监承担对齐（alignment）、编排（orchestration）与交付（delivery）职责。该结构在认知劳动分工理论上呼应了"将复杂任务分解为可被专家子项分别优化的子任务"这一经典原则。

---

## 2. 相关工作与理论依据

PEP 的成员构成遵循"**以证据确定团队**"的方法论：先行检索学界与工业界已有的科研协作方案，再做交集收敛，而非依赖设计者直觉。三类被检索并交叉验证的方案如下。

### 2.1 Harvard Kempner 研究所科研管线
Kempner 研究所提出的研究管线将科研工作显式建模为顺序阶段：*Literature → Hypothesis → Design → Execution → Analysis → Writing*。其价值在于提供了"科研职能的完备最小化集合"参照，PEP 据此确保六名成员对应该管线的关键职能节点。

### 2.2 ReputAgent 多智能体科研团队
ReputAgent 以约 8 个角色（含文献、方法、实验、写作、评审等）构建科研协作智能体群，验证了"多角色并行 + 评审闭环"可提升产出可信度。PEP 吸收了其对"评审/把关（gatekeeping）"角色的显式设置。

### 2.3 阿里云 AI 科研团队
阿里云提出的 5 人 AI 科研团队以"导演 / 文献 / 数据 / 算法 / 写作"组织协作，强调由一名中枢角色（导演）统一调度。PEP 据此设立"研究总监"作为编排中枢。

### 2.4 方案收敛（Convergence）
三条方案在角色集合上高度重叠，其交集可稳定映射为六类职能：**总控 / 文献 / 设计 / 分析 / 写作 / 评审**。由此 PEP 将团队定为 **1 主理人 + 5 专员** 的扁平结构（见图 1），在覆盖主流管线全部关键节点的同时，将角色数控制在沟通开销可接受的范围内。

## 3. 系统架构

PEP 采用**编排式多智能体（orchestrated multi-agent）**架构：

- **编排层（Orchestration）**：由研究总监"毕成稿"承担，负责将用户目标分解为子任务、分派给对应专员、汇总中间产物并控制阶段流转与最终交付。
- **专家层（Specialist）**：五名专员各持专门化系统提示（system prompt）与工具边界，仅在职责域内行动。
- **契约层（Contract）**：成员间通过结构化的中间产物（检索报告、研究方案、数据集、图表、稿件、审稿意见）传递信息，降低隐性依赖。

```
                        用户目标
                           │
                    ┌──────┴──────┐
                    │  毕成稿     │  ← 研究总监（编排/对齐/交付）
                    │ (Orchestrator)│
                    └──┬───┬───┬──┘
          ┌────────┬───┴───┴───┬────────┐
          ▼        ▼           ▼        ▼
      林阅川    计方成       舒析     朱执笔
   文献综述   研究设计     数据分析   学术写作
   研究员     专家         专家      专家
                                          │
                                          ▼
                                       顾平（同行评审专家）
                                      0–100 评分 + 逐条意见
```

*图 1：PEP 扁平化编排架构。评审作为闭环把关节点嵌入交付前。*

## 4. 成员角色与专业分工

| 成员 | 角色 | 专业职责 |
|------|------|----------|
| **毕成稿**（主理人） | 研究总监 | 选题澄清、任务编排、进度跟踪与最终交付 |
| **林阅川** | 文献综述研究员 | 系统检索、综述撰写、研究空白（Gap）分析、引用核验 |
| **计方成** | 研究设计专家 | 研究假设构建、实验/调研方案设计、统计方法选型 |
| **舒析** | 数据分析专家 | 统计检验、机器学习实验、学术图表绘制 |
| **朱执笔** | 学术写作专家 | IMRaD 结构写作、学术润色、期刊格式适配 |
| **顾平** | 同行评审专家 | 0–100 综合评分、逐条审稿意见、引用与事实核验 |

六名成员覆盖从"问题定义"到"可投稿件"的全链条，且评审职能独立设置，避免"作者自评"带来的乐观偏差。

---

## 5. 内置工作流

PEP 将科研协作抽象为可一键触发的三类工作流，并保留单角色直调路由。

### A. 论文全流程（选题 → 定稿，8 阶段）
沿第 1 节所述八阶段顺序推进，由研究总监串联各专员，产出可直接进入投稿评审的完整稿件。

### B. 文献综述（Literature Review）
由林阅川主导，输出结构化综述、时间线/主题地图与研究空白清单，可作为工作流 A 的前置环节独立调用。

### C. 论文评审（Peer Review）
由顾平主导，对任意提交稿件给出 0–100 评分与逐条修改意见，并核验引用与事实一致性，构成质量闭环。

### 单角色直调路由
用户可绕过编排层直接指定某名专员执行单点任务（如"只做统计检验""只润色讨论部分"），兼顾灵活性与专业性。

---

## 6. 评审与质量保障

质量保障由**顾平（同行评审专家）**独立承担，采用 0–100 量化评分框架配合逐条定性意见，并强制进行引用与事实核验。该"生成—评审"解耦设计借鉴 ReputAgent 的把关闭环，显著降低单一智能体自我确认（self-confirmation）带来的错误累积风险。

---

## 7. 分类与平台集成

- **平台分类**：数据智能（**04-DataAI**）。归类理由为核心产出为数据驱动的研究论文，分析职能为链路枢纽。
- **集成方式**：以 WorkBuddy 插件（plugin）形态注册至 `my-experts` marketplace，用户于【专家中心 → 我的专家】即可调用。
- **可移除性**：整个专家团为自包含目录，删除即卸载，不影响其他专家。

## 8. 应用示例

- 规划研究路线：「帮我规划一篇 *X* 方向论文的完整研究路线」
- 文献前置：「针对主题 *Y* 生成系统文献综述与 Gap 分析」
- 评审闭环：将初稿提交 PEP，由顾平给出评分与修改清单后迭代
- 单点调用：「只对该数据集做假设检验并出图」

## 9. 局限与未来工作

**局限**：(1) 成员构成为对公开方案的收敛，未针对特定学科（如实验科学 vs. 计算社会科学）做细粒度调参；(2) 评审闭环依赖智能体自身一致性，尚缺与外部真值库（如已发表数据集、可复现基准）的强绑定；(3) 当前未内置文献数据库直连接口，检索依赖通用检索能力。

**未来工作**：(1) 引入学科适配器（discipline adapter）以支持领域特定方法学；(2) 将评审意见与外部引用库/可复现性检查器联动；(3) 增加人类在环（human-in-the-loop）确认节点，提升高风险结论的可信度。

---

## 10. 结论

论文研究专家团（PEP）以"证据驱动的团队构成 + 编排式多智能体架构 + 解耦的评审闭环"，为学术研究提供了可复用、可审计、可移除的协作基础设施。其价值不限于效率提升，更在于通过**明确的职责边界与稳定的接口契约**，使科研辅助过程具备可追溯性与可批判性——这正是学术工作对自动化工具的核心要求。
