# 理论依据与团队构成方法论（Methodology）

本文档说明「论文研究专家团（PEP）」为何以 **1 主理人 + 5 专员** 的扁平结构组织，及其角色集合的来源。

## 方法论原则：以证据确定团队

团队构成不依赖设计者直觉，而是先检索学界/工业界已有的科研协作方案，再做交集收敛。这样可在「职责覆盖度」（不漏关键职能）与「协作冗余度」（不过度拆分）之间取得平衡。

## 被检索并交叉验证的三类方案

| 方案 | 角色/阶段要点 | 对 PEP 的贡献 |
|------|--------------|---------------|
| **Harvard Kempner 研究所科研管线** | Literature → Hypothesis → Design → Execution → Analysis → Writing | 提供科研职能的"完备最小化集合"参照 |
| **ReputAgent 多智能体科研团队** | 约 8 角色，含文献/方法/实验/写作/评审，多角色并行 + 评审闭环 | 确立"评审/把关"角色须显式独立 |
| **阿里云 AI 科研团队** | 导演 / 文献 / 数据 / 算法 / 写作 五人协作 | 确立"中枢编排角色（总监）"必要 |

## 收敛结果

三类方案在角色集合上高度重叠，其交集稳定映射为六类职能：

```
总控(Orchestrator) ── 文献(Literature) ── 设计(Design)
                                    └── 分析(Analysis) ── 写作(Writing) ── 评审(Review)
```

由此确定为：

- **1 主理人**：毕成稿（研究总监）——对应 Kempner 的管线统筹与阿里云"导演"。
- **5 专员**：林阅川（文献）、计方成（设计）、舒析（分析）、朱执笔（写作）、顾平（评审）——覆盖 Kempner 关键节点，并显式保留 ReputAgent 的评审闭环。

## 设计权衡

- **为何不是 8 角色**：ReputAgent 的细分角色（如方法/实验拆分）在本专家团中由「设计 + 分析」两角色协同覆盖，避免过度拆分带来的编排开销。
- **为何保留独立评审**：生成与评审解耦可降低单一智能体自我确认（self-confirmation）导致的错误累积。
- **为何扁平而非层级**：六名成员向总监单线汇报，减少多层级通信损耗，契合中小科研协作的实际规模。
