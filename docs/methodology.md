# 团队构成的方法依据

这份文档说明「论文研究专家团」为什么是 **1 名统筹者 + 5 名专员**，以及这个角色集合从哪来。

## 定角色的办法：先查，再定

我没有凭直觉分配角色。做法是先把学界和工业界已有的科研协作方案查一遍，看它们在角色划分上有没有共识，然后取交集。这样能在两件事之间取得平衡：职责不能漏（覆盖度），人也不能太碎（协调开销）。

## 查到的三套方案

| 方案 | 角色 / 阶段 | 对这套专家团的影响 |
|------|------------|-------------------|
| **Harvard Kempner 研究所科研管线** | Literature → Hypothesis → Design → Execution → Analysis → Writing | 提供了科研职能的"最小完备集合"参照 |
| **ReputAgent 多智能体科研团队** | 约 8 个角色，含文献 / 方法 / 实验 / 写作 / 评审 | 确认评审角色必须独立设置 |
| **阿里云 AI 科研团队** | 导演 / 文献 / 数据 / 算法 / 写作 五人协作 | 确认需要一名中枢角色做统筹 |

## 交集

三套方案重叠得很稳定，六类职能：

```
总控 ── 文献 ── 设计 ── 分析 ── 写作 ── 评审
```

对应下来就是：

- **1 名统筹者**：毕成稿（研究总监）——对应 Kempner 的管线统筹与阿里云的"导演"。
- **5 名专员**：林阅川（文献）、计方成（设计）、舒析（分析）、朱执笔（写作）、顾平（评审）——覆盖 Kempner 的关键节点，并保留 ReputAgent 的独立评审。

## 几个取舍

**为什么不是 8 个角色。** ReputAgent 把方法和实验拆成独立角色。我这里把它们并入"设计"与"分析"：设计给出方案，分析执行方案，两者本来就是前后手关系，中间再加一个角色只会多一次交接。

**为什么评审必须独立。** 写稿的自己检查稿子，等于让作者给自己打分。评审者拿到的只有成品，看不到写作过程，这是它能挑出问题的前提。

**为什么是扁平而不是分层。** 六名成员都向统筹者单线汇报。再往上加一层，通信开销的增长快于协调收益——这个规模不值得。

**为什么中间产物要显式化。** 检索报告、研究方案、数据集、图表、稿件、审稿意见，每一步都落成具体对象。出错时能定位到环节，而不是整篇推倒重来。
